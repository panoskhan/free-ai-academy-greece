Η διεπαφή του εργαλείου

Ένα καλό εργαλείο ξεκινά από μία σαφή διεπαφή: τι εισάγει ο χρήστης, τι παίρνει πίσω και τι κάνει όταν κάτι πάει στραβά.

Φτιάξε τη φόρμα με labels για κάθε πεδίο και ένα κουμπί υποβολής.

Κανόνας Academy: Κάθε πεδίο εισόδου χρειάζεται label. Ο χρήστης πρέπει να ξέρει τι να γράψει.

Πρακτική άσκηση 1: Φτιάξε τη φόρμα

Δημιούργησε μια φόρμα με ένα πεδίο κειμένου και ένα κουμπί.

Τι πρέπει να έχει κάθε πεδίο εισόδου;

Validation και καταστάσεις

Πριν στείλεις κάτι στο AI, έλεγξε την είσοδο: να μην είναι κενή και να μην ξεπερνά ένα λογικό μέγεθος.

Δείξε καταστάσεις φόρτωσης και σφάλματος, ώστε ο χρήστης να ξέρει τι συμβαίνει.

Κανόνας Academy: Ποτέ μην αφήνεις το εργαλείο να «σιωπά». Κάθε κατάσταση πρέπει να φαίνεται στον χρήστη.

Πρακτική άσκηση 2: Πρόσθεσε έλεγχο εισόδου

Πρόσθεσε έλεγχο για κενή είσοδο και για είσοδο πάνω από ένα όριο χαρακτήρων, με μήνυμα σφάλματος.

Τι πρέπει να κάνει το εργαλείο όταν η είσοδος είναι κενή;

Ο δρόμος προς τον server και τα κλειδιά

Ένα εργαλείο AI συνήθως περνά από browser, server και μετά από το μοντέλο. Το κλειδί API πρέπει να μένει μόνο στον server.

Όποιος βλέπει τον κώδικα του browser, δεν πρέπει να μπορεί να βρει το κλειδί.

Κανόνας Academy: Κλειδί API μέσα σε αρχείο που ανεβαίνει σε δημόσιο repository είναι διαρροή. Αν συμβεί, ακύρωσε το αμέσως.

Πρακτική άσκηση 3: Σχεδίασε τη διαδρομή

Γράψε σε ένα αρχείο ΤΙ περνά από browser, server και AI, και πού μένει το κλειδί.

Πού πρέπει να μένει το κλειδί API;

Δοκιμές και παράδοση

Δοκίμασε το εργαλείο με κενή είσοδο, με πολύ μεγάλη είσοδο, με επιτυχία και με αποτυχία. Κάθε περίπτωση πρέπει να έχει σαφές αποτέλεσμα.

Γράψε README με τον τρόπο εγκατάστασης και ανάπτυξης.

Κανόνας Academy: Ένα εργαλείο είναι έτοιμο όταν ο χρήστης καταλαβαίνει τι κάνει και ένας άλλος άνθρωπος μπορεί να το τρέξει.

Πρακτική άσκηση 4: Κάνε τις τέσσερις δοκιμές

Δοκίμασε τις τέσσερις περιπτώσεις και σημείωσε το αποτέλεσμα κάθε μίας.

Ποια είναι η σωστή σειρά δοκιμών για ένα εργαλείο;
